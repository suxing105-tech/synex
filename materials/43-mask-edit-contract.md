# 43 · 再次创作的遮罩编辑（2026-11-12）

单图局部重绘那条工作流随包内置，代价是它依赖一套第三方（孤海工具节点）的私有约定；把「画遮罩」
做进再次创作弹窗之前先把这套约定钉死成文档，后面排查静默失效只照这一份对。

## 1. 遮罩到底怎么进工作流（孤海契约）

出处：`custom_nodes/Goohaitools-comfyui/nodes/加载图像.py`。

| 事实 | 位置 | 后果 |
|---|---|---|
| `LoadImageGoohai.RETURN_TYPES = ("IMAGE","MASK","STRING")`，MASK 是第 2 个输出 | `:40` | 槽位检测按「有没有 MASK 输出」认遮罩位，不看节点名 |
| `is_clipspace = "[input]" in str(image)` | `:158` | 上传时路径值必须以 `  [input]` 结尾，否则不走剪贴板分支 |
| 文件名不含 `clipspace-mask-` 时，透明区会被刷白 | `:217-220` | 遮罩文件必须叫 `clipspace-mask-<digest>-<n>.png`，命名是功能的一部分 |
| `MASK = 1 - alpha/255` | `:256-295` | 我们交出去的是「透明 = 要改」的透明 PNG，不是黑白图；黑白只在预览/导出时现推 |
| `IS_CHANGED` = 文件 sha256 | `:314-329` | 换一次遮罩就是换一份文件，天然不命中旧缓存；同名不同内容也认得出来 |
| 涂到的像素 < 10 时按全白处理 | 同上 | 前端 `MASK_EMPTY_PIXELS = 10`：低于它算「没画」，别交一份等于没画的遮罩 |

官方 `LoadImage` 同样是 alpha→MASK（根 `nodes.py:1747/1772`），但 `LoadImageMask` v1 不吃 alpha
（`nodes.py:1795/1824`），所以**别人导入的 `LoadImageMask` 类工作流仍然不支持**，检测也不会把它
标成遮罩位。这条是能力边界，不是 bug。

## 2. 槽位的四条新约定（前后端同名）

| 键 | 含义 | 谁写 | 谁读 |
|---|---|---|---|
| `mask: "alpha"` | 这一格的图能吃遮罩 | 检测 `clone_templates._mask_consumers`（顺着 MASK 输出找消费者） | 前端决定画笔出不出、后端决定收不收这格的 masks |
| `allow_empty: true` | 提示词留空是一个模式（这条工作流＝移除） | 随包模板写死 | `canGenerate` 放行 + 后端把「留空」从 422 改成按槽位判 |
| `empty_hint` | 留空时到底干什么，一句话 | 随包模板写死 | 卡底常驻那行、编辑层顶栏的提示 |
| `sync_to: [[node,input],…]` | 一颗旋钮管多台节点（两台采样器的步数） | 检测 | 前端写值时一起写、后端回填 |

**扩位继承母槽**：一台加载器克隆出来的第 N 个参考位照样带 `mask`，`referenceCells()`
（前端）与 `reference_cells()`（后端）同口径。丢了这条，扩位那一格就悄悄不能画遮罩。

## 3. 一次带遮罩的生成走什么路

1. 前端 `MaskEditor` 画完 → `MaskEdit{png(裸 base64 透明 PNG), tint, coverage, pixels, imageId}`。
2. `maskRequestPayload()` 只带真画过的格子；一张没画就整个 `masks` 键都不出现（老请求体一字不改）。
3. 后端 `decode_mask_png`：剥 `data:` → 空报「是空的」→ >12MB 拒 → 解不开报「不是读得开的图片」→ 长边 >4096 拒。
4. `compose_mask_png`：把遮罩按参考图尺寸 LANCZOS 对齐，`RGB + putalpha(invert(L))` 合成透明 PNG。
5. 上传文件名保留 `clone_sources` 那份源图 sha1[:8]，前缀 `clipspace-mask-`，值尾加 `  [input]`。
6. `masks` 不进 `public_state()` 白名单 → 不广播、不落库：它是这一次的参数，不是任务的一部分。
7. `ValueError → 400`、`CloneUnavailable → 409`、`KeyError → 404`（`routes/clone.py:332-336`）。

## 4. 编辑器的三条设计（定了就不动摇）

1. **画布只看 alpha**：涂没涂到是唯一事实，红色是给人看的第二层。提交那份黑白图在导出时用
   `fill 黑 → destination-out 画 mask → destination-over 填白` 三步现推（逐像素循环在 4096² 上会卡手）。
   所以「换个颜色」「调叠色不透明度」永远不会悄悄改变送给 ComfyUI 的东西。
2. **撤销不存像素快照**：2048² 的 RGBA 一张 16MB，存 40 步就是 600MB。这里存笔迹
   `Stroke{op,r,pts}`，撤销/重做/清空/改叠色都走整条重放。
3. **手势与图库放大层对齐**：左键画、滚轮缩放、Ctrl+滚轮改笔刷、双击 100%⇄适应、空格临时抓手、
   `B`/`E`、`Ctrl+Z`/`Ctrl+Shift+Z`/`Ctrl+Y`、`+−0`。唯一例外是左键归画笔，所以平移只能靠空格或中键。

配套口径：画布尺寸 = 参考图尺寸，长边超 4096 先降；两个事件位置之间补点（否则快拖成虚线）；
`onDone(null)` = 这格其实全擦了，调用方连键一起删；换参考图/换工作流时那条遮罩作废并 toast 说明。

## 5. 交互上定了的几个歧义点

- **入口在哪**：大图左上角「画遮罩 / 改遮罩」。文案区分第一次和第二次，别让人以为进去是看一遍。
- **大图摆谁的图**：能画遮罩的那一格里的图，不是被点的那张卡。画遮罩必须看得见落点。
- **点进去之后**：盖住整块弹窗的一层（`.cm-backdrop` 的孩子、`.cm-panel` 的兄弟），不是挤在左栏里的一块。
- **改提示词怎么办**：编辑层里只读回显模式和提示词摘要，要改就退出编辑层——就地改会画完还得退出去。
- **跑完之后这一格给谁**：默认给新产出，右上角「回看参考图」切回去看范围落在原图哪儿，再点回来。
- **没画遮罩就生成**：放行，但先 toast 一句「这一次没有局部范围」；提示词全擦/遮罩全擦同理。
- **Esc**：第一下只退编辑层，按「取消」算，这次画的不要。
- **随包模板**：不给点「重新检测槽位」（后端 409），按钮留着说清原因。

## 6. 已知偏离与风险

- 原计划里的「手动勾选支持遮罩」没做：检测已经自动，手动强开一条 MASK 没人用的格子只会做出一份
  ComfyUI 会拒的图。要支持别的节点，正确做法是扩 `_mask_consumers` 的检测，不是给用户一个开关。
- 异机缺孤海节点、或缺 `万物移除Remove` / `一致性无偏移` LoRA 时，`/prompt` 会拒；这是模板依赖，
  不是遮罩链路的问题。
- alpha→MASK 是第三方私有约定，孤海升级可能静默失效。回归点：`<10 像素算空`、`clipspace-mask-` 前缀、
  `  [input]` 尾巴，三处任一变了都会「看着成功、其实整张重画」。
- 带遮罩的每次生成多一次上传 + 一次像素比对。
- 云端模板不吃本地透明 PNG，`maskTemplate` 直接排除。
