# 文件夹交互与删除监听排查记录

日期：2026-09-18。

- FolderTree 原先递归渲染所有子项，无展开状态，无双击、长按事件；只有菜单中的改名和逐级上移/下移。
- 来源目录由路径映射生成。此次改名定义为图库显示名称；同级排序不修改路径或 parent_id，重新索引也保留显示名称。
- Indexer._pending 为路径集合，但刷新时对整批使用最后一个事件类型；混合删除、新建、修改事件会互相干扰。
- 目录删除原先直接跳过；Windows 只发送目录删除事件时可能残留其后代图片索引。
- WebSocket 已有单图删除分支，但缺少目录计数更新，以及在途 feed/detail 请求返回旧数据的保护。
- 来源目录默认 order 均为 0，原先名称参与排序；改名之前固定当前顺序，避免改名导致跳位。
- 实际浏览器验证：在本地新前端中单击“剧集”后子目录收起，双击弹出改名窗口并说明只改显示名称；取消后未修改用户目录数据。
- 项目原有未跟踪文件保持原样，未加入本次提交。

## 桌面打包复测

- 真实打包程序的文件监听测试发现：Windows watchdog 的 FILE_ACTION_REMOVED 无论文件还是目录都会包装为 FileDeletedEvent。只依据 is_directory 的清理仍会遗漏目录后代。
- 补充按已索引路径前缀清理后代的兼容处理，参数化回归测试覆盖 is_directory=True/False。
- 更新后的 PyInstaller 后台实测通过：启动、导入、来源显示名称、排序、混合删除/新增、整个目录删除、统计清零。
- 使用 Tauri 生成本地 NSIS 安装包，关闭本次自动更新签名产物生成；未读取签名私钥，未发布线上更新。
- 新桌面进程及后台均来自 outputs/folder-interactions-v1/package/app/，已确认启动并通过桌面窗口双击改名验证。旧安装版已正常关闭，保留用户原数据。
