# 导入图片错用旧预览缓存

现场证据（只读核对）：桌面“人物三视图.jpg”和图库保存的“人物三视图_1.jpg”SHA256 完全一致，尺寸均为 3967×3000；ID 171 的旧缓存 171_max1024.webp 却是另一张古装人物图，尺寸 1024×572。记录见 observations.json。

根因：旧预览只用图片 ID 和目标尺寸命名，仅以缓存 mtime >= 原文件 mtime 判定有效。保留旧时间戳的导入、同编号的历史缓存、文件替换都可能误命中。浏览器一年 immutable 缓存还会延长错误显示。

修复：
- 预览缓存名包含原文件内容 SHA256、目标尺寸和编码质量；读取同一字节快照解码，临时文件写完后原子发布。
- 忽略无内容标识的旧预览，不删除用户图片。现有缓存会在请求时自动被正确内容替代。
- 预览 URL 升级版本并保留亚秒时间及文件身份，避开浏览器旧 URL 缓存；HTTP 使用内容 ETag 和 private, no-cache。仅 Last-Modified 相同不能判断内容一致。
- 选中样式改为覆盖在图片之上的 1px 细线，去掉原 6px outline，不影响图片尺寸。

验证：用户原图只读生成正确预览 1024×774，与标准等比缩小参考的平均像素误差约 1.53/255，原文件哈希未改变。自动化覆盖历史缓存、相同 ID 不同文件、同路径同时间戳替换、条件请求及缓存命中；打包后台注入错误红图缓存后验证返回正确蓝图和各自比例。
