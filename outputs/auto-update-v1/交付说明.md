# 苏醒图库 v0.2.0 · 自动更新第一版

## 安装使用

安装包：`苏醒图库_0.2.0_x64-setup.exe`，与本说明在同一目录。

1. 关闭旧版图库及本次运行的测试版窗口。
2. 运行安装包，沿用现有安装位置。
3. 启动后打开「设置 → 软件更新」。

从 v0.1.0 升级需要手动安装这一次。GitHub 发布入口已配置为 `suxing105-tech/synex`，但本次没有上传 Release；正式发布更新清单前，检查更新会提示暂时无法获取更新信息，不影响图库使用。

当前运行的是 `outputs/auto-update-v1/app/` 中的测试版。测试版不覆盖已安装的软件，便携运行时禁止应用内安装；请使用上述安装包完成正式安装。

## 已有功能

- 启动后约 15 秒检查；检查成功后 24 小时内不重复，失败后至少间隔 15 分钟重试。
- 支持关闭自动检查、手动检查、查看版本说明、下载进度和确认安装。
- HTTPS 下载并验证更新签名，验签失败不能安装。
- 导入或保存过程中拒绝安装；安装前冻结写入并备份 SQLite 数据库和设置。
- 退出自有后台、确认端口释放后再交给安装程序；启动安装程序失败时尝试恢复后台。
- 同版本重复启动会唤起已有窗口；不同旧版本仍可能占用端口，需要先关闭。
- 只有安装记录唯一且与当前运行位置一致时，才允许应用内安装。

备份保存在图库数据目录上级的 `update-backups/`，包含数据库、设置和版本记录。原图片保留在原文件夹，不复制到更新备份中，也不会被安装流程删除。暂不提供自动回滚。

## 后续发布

1. 同步更新 frontend/package.json、frontend/src-tauri/Cargo.toml、frontend/src-tauri/tauri.conf.json、backend/pyproject.toml 和 backend/app/version.py 中的版本号。
2. 更新本目录的 release-notes.md。
3. 在项目根目录运行 `frontend/scripts/build-update.ps1`，生成签名安装包、对应 `.sig` 和 `latest.json`。
4. 在指定 GitHub 仓库创建对应的稳定版 Release，例如 `v0.2.0`，将这三个文件上传到同一次 Release，设为 Latest 后发布。不要上传整个 outputs 文件夹。
5. 发布前仍需完成两版本之间的真实覆盖升级测试，包括 UAC 取消、升级后启动和原数据核对。

签名私钥保存在本目录的 `private/updater.key`，已排除在 Git 之外。请妥善备份；后续版本必须沿用同一私钥。安装包中只包含公钥。测试密钥也位于 private/，不能用于正式发布。
