# 导入 ComfyUI 输出目录：文件夹选择功能方案

状态：规划，尚未修改应用功能。日期：2026-09-09。

## 1. 第一版目标

在现有路径输入框右侧增加「选择文件夹」按钮。点击后打开 Windows 系统文件夹选择窗口，选择 ComfyUI 的 output 目录并确认，路径自动填入输入框。仍可手动输入或粘贴路径。

选完只填入路径，不自动扫描、不保存设置。点击「开始导入」后，才校验、保存监听目录并启动扫描。ComfyUI 无须保持运行，只要目标目录可访问。

## 2. 界面与操作

保留当前深灰背景和红色主按钮；「选择文件夹」为边框次级按钮，避免与「开始导入」争夺注意力。

```text
导入 ComfyUI 输出目录
选择或输入输出文件夹，导入其中的图片和生成信息。

目录路径
[ D:\ComfyUI\output             ] [选择文件夹]
建议选择 ComfyUI 的 output 文件夹，包含其子文件夹。

试用示例目录

[暂不导入]                           [开始导入]
```

- 弹窗宽度按按钮加入后的空间适当增加；窄窗口下按钮可换行，不能挤掉输入框。
- 路径输入框保持单行，可水平滚动、复制和修改；长路径可通过悬停查看完整内容。
- 文件夹窗口标题为「选择 ComfyUI 输出文件夹」，每次选一个目录，不能选择单个文件。
- 首选打开输入框中有效的目录，其次使用最近成功导入且仍存在的目录，最后使用系统默认位置。不要递归搜索整台电脑。
- 取消文件夹选择时，保留原输入内容，不显示错误、不更改设置。
- 弹出文件夹窗口期间禁止重复打开；若主导入弹窗已关闭，迟到的选择结果不再写回。
- 示例目录保留为次级入口；不将示例路径默认当成用户真实的 output 路径。

## 3. 路径校验与提示

选择返回后可进行轻量预检；点击「开始导入」时，后台再次检查路径，避免文件夹在选择后被移动或磁盘断开。预检不扫描整棵目录树，不修改设置。

| 情况 | 处理 |
| --- | --- |
| 路径为空 | 禁用开始导入 |
| 路径不存在或实际为文件 | 输入框下提示「文件夹不存在，请重新选择」或「请选择文件夹」 |
| 无读取权限或网络目录暂时不可用 | 提示「无法访问该文件夹，请检查权限或连接」；保留已选路径 |
| 目录名不是 output | 允许导入；不要仅凭目录名称拦截用户的自定义输出目录 |
| 空目录或没有支持的图片 | 允许保存监听；扫描完成显示「暂无可导入图片，后续新增图片可自动收录」 |
| 中文、空格、不同盘符、UNC 路径 | 使用原生路径对象和 JSON 传递；可访问则支持，不拼接为 shell 命令 |
| 同一目录的不同写法 | 规范化后去重，Windows 比较处理大小写和末尾分隔符 |
| 扫描中再次点击 | 禁用重复提交及路径修改；显示现有扫描进度 |
| 部分子目录不可读 | 显示扫描警告与失败统计，不虚报完整导入成功 |

错误显示在弹窗内，使用中文；具体异常保留到日志。扫描失败时保留路径，允许重试。选择器取消与失败要区分。

## 4. 监听目录的保存规则

当前实现会用 `[新路径]` 覆盖 watch_dirs，导致原有目录停止监听。建议在本次导入改动中一起修正：

1. 后台校验路径通过后，读取最新监听设置，将规范化后的新目录追加并去重。
2. 保留已有监听目录；已存在的目录可以重新扫描，但不重复加入列表。
3. 校验失败不改设置；启动扫描失败要明确提示「目录已添加，但扫描未启动，可重试」，不得显示成功。
4. 尽量通过一个导入提交接口协调校验、追加和扫描，而不是由前端先读后覆盖整个列表；与更新维护期间的写入保护兼容。

该规则不会删除原图片或已有图库记录。选择文件夹本身没有写入副作用。

## 5. 技术落地

- 桌面端采用 Tauri 官方 Dialog 插件，通过 Rust 封装一个只选择单个目录的命令。将对话框关联到当前主窗口，异步返回路径或取消结果。
- 前端沿用现有 Tauri 适配层，统一返回「已选择」「已取消」「不可用/失败」结果。系统选择器负责选择，Python 后台负责实际可访问性校验与导入。
- 仅提供主窗口需要的目录选择入口，不增加通用文件读写能力。
- 浏览器模式保留手动输入，说明路径应位于图库后台所在电脑；不将浏览器选择的上传文件列表冒充后台的本机绝对路径。
- 第一版不增加多目录多选、拖拽文件夹、自动查找 ComfyUI 或自绘文件浏览器。

主要修改现有文件：

- `frontend/src/components/OnboardingModal.svelte`：按钮、选择状态、错误提示和导入状态。
- `frontend/src/lib/tauri.ts`：目录选择适配。
- `frontend/src-tauri/Cargo.toml`、`frontend/src-tauri/src/lib.rs`、`frontend/src-tauri/src/commands.rs`：插件和受限目录选择命令。
- `backend/app/routes/settings.py`、`backend/app/indexer.py`：路径验证、保留已有监听目录及扫描反馈。
- `frontend/src/lib/api.ts`：如采用统一导入接口，同步接口调用。

「设置 → 监听目录」也适合复用该选择器，建议作为紧随其后的第二步；第一版先完成截图中的导入窗口。

官方依据：https://v2.tauri.app/plugin/dialog/ 。官方插件支持 Windows 原生选择窗口，返回文件系统路径，并可从 Rust 调用。

## 6. 开发顺序与验收

顺序：桌面目录选择命令 → 输入框与按钮联动 → 后台校验及追加目录 → 扫描状态和错误处理 → 自动测试与 Windows 实测 → 构建新安装包、Git commit。

验收必须覆盖：

1. 在真实 Windows 桌面打开选择窗口，选中文及空格目录，完整路径正确回填。
2. 取消选择、关闭弹窗、连续点击都不产生意外保存或重复窗口。
3. 手动输入继续可用；浏览器模式不崩溃且不调用原生功能。
4. 无效路径与权限失败不改原设置；校验后目录被移除时仍能正确报错。
5. 已有多个监听目录时，新目录追加、旧目录保留，同目录不重复。
6. 正常扫描及子目录图片可以导入；空目录提示正确；失败时可重试。
7. 导入过程中禁止重复提交，并兼容自动更新的写入保护。
8. 新安装包中目录选择功能可用，不依赖开发环境；完成相关前端、后端和 Rust 回归测试。

本次仅提交方案和依据检查，不代表以上功能或未来验收已完成。
