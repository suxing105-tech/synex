设置页能看见并恢复被删掉的内置工作流：把单向门改成双向门

删内置工作流以前只有「拉黑」没有反悔：meta 里的名单看不见，删错只能进库改。
v0.2.31「音频少一种模式」就是这个洞的真实代价，所以补门而不是只补那一次。

- 接口：GET /api/clone/templates/hidden（随包清单里被删且库里确实没有的那几条）、
  POST /api/clone/templates/hidden/{key}/restore。404=根本不在隐藏名单，
  409=名字被别一条占着（模板名唯一索引），话术里直接给下一步。
- restore 不另开一套插入逻辑，摘掉名单后走 seed()：槽位、默认台词、
  「同族已有当前就不当当前」这些规矩因此只有一份。
- 撞名分两种，都是既有装载规矩、不新立：用户自己导过同名的 → 认领那一条
  （内容留他的，bundled_sha 记随包指纹，两者不等＝以后更新不覆盖）；
  名字被别一条内置占着 → 409。
- 随包清单读不出来时隐藏列表返回空表，不把设置页拖崩；老后端没这个接口时
  前端 catch 成空数组，模板列表照常用。
- 前端只认带 key 的条目：/templates/hidden 是 /templates 的前缀扩展，
  按前缀路由的预演很容易把模板答话喂给它。

验证：后端 34 passed（新 8 条）、vitest 1271（新 3 条）、svelte-check 0 errors/20 warnings。
真机 HTTP 走一遍（uvicorn :8899 + 真实库副本，不碰 _clone_r10_data 本体）：
隐藏列表空 → 删掉参考音色(id 11) → 列表里出现它 → 恢复(id 14，不抢「当前」) →
列表又空 → 再恢复回 404。记录 outputs/hidden-builtin-restore-v1/live_check.txt。
