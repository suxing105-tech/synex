# AI 图库管理器 MVP — 产品设计文档

> 状态：草案 v0.1 · 更新日期：2026-09-01

## 1. 背景与目标

随着 ComfyUI 等 AIGC 工作流的普及，个人创作者往往在本地累积数千到数万张 AI 生成图。原生文件管理器只能按文件名查找，无法利用 prompt、模型、seed 等关键元数据快速定位"那张图"。

**目标**：打造一个面向 ComfyUI 用户的轻量级本地图库管理器，让"找回那张图"从分钟级降到秒级。

**核心价值**：基于 prompt 与生成参数的全文检索 + 完整元数据回溯。

## 2. 目标用户与场景

| 用户类型 | 主要场景 |
|---------|---------|
| 个人 ComfyUI 重度用户（数千~数万张图） | 复盘调参过程、二次创作、对外展示 |
| AIGC 内容创作者 | 整理 portfolio、为后续创作找参考 |
| AI 绘画研究者 | 对比不同 checkpoint / LoRA / sampler 效果 |

**MVP 仅服务单机、单用户场景**。

## 3. MVP 范围

**包含**
- 本地文件夹监听导入（主：ComfyUI 输出目录）
- PNG / WebP 元数据自动解析
- 网格浏览、详情查看、搜索筛选
- 标签 + 收藏夹
- 本地 SQLite 索引 + 原文件原地存放

**不包含（明确排除）**
- 团队协作 / 多用户 / 云同步
- ComfyUI 工作流编辑与重跑
- AI 二次生成（inpainting / outpainting）
- 对外分享、版权水印
- 移动端
- Grid 子图自动拆分入库（放到 P1）

## 4. 功能分级

### P0 — MVP 必须有

| 功能 | 说明 |
|------|------|
| 文件夹监听导入 | 监听指定目录的新增 / 变更 |
| PNG / WebP 元数据解析 | 解析 ComfyUI 写入的 prompt 与 workflow 两个 JSON chunk |
| 缩略图缓存 | 避免重复解码原图 |
| 网格浏览 | 缩略图瀑布流，按时间倒序 |
| 详情页 | 大图 + 元数据面板 + prompt 一键复制 + 原始 JSON 折叠 |
| 全文搜索 | prompt 内容、文件名、标签 |
| 筛选器 | checkpoint、LoRA、收藏、日期范围 |
| 标签管理 | 手动添加 / 删除 / 重命名 |
| 收藏夹 | 单标签收藏，跨视图过滤 |

### P1 — 第二版加入

- Grid 子图拆分入库
- 多选 + 批量打标签 / 删除 / 移动
- AI 自动打标签（CLIP 本地模型）
- 相似图搜索（向量检索）
- 重复图检测（pHash）
- 暗色 / 亮色主题

### P2+ — 后续探索

- 跨设备同步
- 团队共享与权限
- 对外分享链接
- 与 ComfyUI API 双向打通（直接调用生成）
- 移动端

## 5. 关键用户流程

### 5.1 首次使用

1. 用户指定 ComfyUI 输出目录
2. 应用扫描目录，建立 SQLite 索引
3. 自动提取每张图的元数据并生成缩略图
4. 扫描完成后跳转到网格视图

### 5.2 浏览与筛选

1. 默认按时间倒序展示
2. 顶部搜索框输入关键词（命中 prompt / 文件名 / 标签）
3. 左侧筛选器：checkpoint、LoRA、收藏、日期
4. 点击缩略图进入详情页

### 5.3 找回某张图

1. 记得 prompt 中的某个词 → 搜索框输入 → 命中
2. 记得某次跑图用的 LoRA → 筛选器勾选 → 缩小范围
3. 完全不记得 → 翻时间线 / 按收藏夹浏览

### 5.4 整理

1. 详情页添加标签 / 加入收藏
2. 多选视图批量打标签（需 P1）

## 6. 数据模型概览

`
Image
  id, file_path, file_hash, mtime, size, width, height
  prompt (positive), negative_prompt
  checkpoint, sampler, steps, cfg, seed, vae
  loras (list of {name, weight})
  favorite (bool), imported_at

Tag
  id, name

ImageTag
  image_id, tag_id
`

- 索引存储：SQLite；元数据 JSON 留原始备份以便回溯
- 缩略图：本地 cache 目录，按 image_id 哈希分片

## 7. 非功能性需求

| 维度 | 目标 |
|------|------|
| 导入吞吐 | 单机 10k 张图首次扫描 < 10 分钟 |
| 浏览流畅 | 1k 缩略图滚动 60fps |
| 搜索响应 | < 200ms |
| 资源占用 | 闲置时内存 < 200MB |
| 可靠性 | 索引可重建，原文件不被修改 |

## 8. 技术选型（待定）

- **形态**：桌面应用（Electron / Tauri）或 CLI 索引器 + Web 前端，待定
- **后端语言**：Python（ComfyUI 生态友好）或 Node.js / Go
- **存储**：SQLite + 原文件
- **缩略图**：libvips 或 Pillow

## 9. 后续迭代方向

1. **V1.1**：Grid 拆分入库 + 批量操作
2. **V1.2**：AI 自动打标签 + 相似图搜索
3. **V2.0**：对接 ComfyUI API，实现"找到 → 改参 → 重跑"闭环
4. **V3.0**：协作与跨端
